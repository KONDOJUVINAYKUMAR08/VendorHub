### Required Microservices (Implement All of These)

You must build the following microservices. Each should own its own data and business logic:

1. **Auth Service**
   - User registration and login (for both Internal users and Vendors)
   - JWT issuance and validation
   - Role-based access (Admin, Reviewer, Vendor)
   - Password hashing
   - Token refresh

2. **Vendor Service**
   - CRUD for vendor profiles
   - Vendor self-registration (via portal)
   - Basic vendor metadata and contacts
   - Search and filtering of vendors

3. **Document Service**
   - Document upload (single + bulk)
   - Document versioning (same filename = new version + history)
   - Document metadata (type, expiry date, status, file path)
   - Actual file storage (local for now, structured for future S3)
   - Expiry tracking

4. **Compliance Service**
   - Real-time risk scoring and status calculation for vendors
   - Business rules for risk (based on document completeness, expiry, rejections)
   - No hardcoded values — make thresholds configurable
   - Compliance status (Active / Under Review / High Risk)

5. **Workflow Service**
   - Approval workflows (multi-stage review: Security → Legal → Procurement)
   - Pending approval queue
   - Approve / Reject actions with comments
   - State management for document reviews

6. **Audit Service**
   - Immutable audit logging of every significant action
   - Queryable audit trail (by vendor, action type, date, user)
   - Must capture who did what and when

7. **Notification Service**
   - In-app notifications
   - Expiry alerts and reminders
   - Workflow status updates
   - Simple notification center (simulate SNS/EventBridge)

### Communication Between Services
- Use **event-driven architecture** where possible (publish/subscribe pattern).
- For local Docker testing, use a simple message broker (e.g., RabbitMQ or just direct HTTP + event simulation via MongoDB change streams or a shared events collection).
- Services should be loosely coupled. For example:
  - Document Service publishes "DocumentUploaded" event
  - Compliance Service and Notification Service react to it

### Database
- Use **MongoDB** for all services (official `mongo` Docker image).
- Each service can use its own database or collections (e.g., auth-db, document-db, audit-db).
- Provide proper indexes.
- Data must persist across container restarts (use volumes in docker-compose).

### Docker & Testing Requirements
- Create a complete `docker-compose.yml` that starts:
  - MongoDB (official image)
  - All 7 microservices
  - (Optional) A simple reverse proxy / API gateway
- The entire backend stack must be testable with `docker-compose up`.
- Include a seed script that populates realistic data (multiple vendors, documents, users with different roles) when the stack starts.
- Frontend can be run separately (`npm run dev`) or added as a service. It must connect to the backend services.
